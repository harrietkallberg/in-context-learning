\section{Reproduction of ICL of linear functions}
% (b) your reproduction, with a short log of what the paper left unspecified and what you had to guess

In this section we reproduce some results obtained by \cite{garg2022what} on ICL of
linear functions.

\subsection{Setup}
We train our own transformer from scratch on an NVIDIA A100 via Modal, following the
setup described in the paper, and evaluate it using the same framework: the same model
(GPT-2, 12 layers, 8 heads, 256-dimensional embeddings), optimiser, curriculum and number
of training steps, and the same evaluation over 1280 prompts with 90\% bootstrap
confidence intervals. The following points were left unspecified by the paper or differ
in our reproduction:
\begin{itemize}
\item \textbf{Number of runs.} The paper does not state how many models were trained for
  its main results, and the authors released one checkpoint per task. We train a single
  run. Neither the paper's code nor ours fixes a random seed, so our error bars reflect
  variation over evaluation prompts only, not over training runs.
\item \textbf{Noise level.} The noise in noisy linear regression is stated as
  $\mathcal{N}(0, 1)$ in Section~4 of the paper and as $\mathcal{N}(0, d/20)$ in
  Appendix~B.2. These coincide for $d = 20$, which we use.
\item \textbf{Software.} We use Python 3.10 instead of 3.8 and a newer version of the
  logging library wandb, since the original versions are no longer supported by our
  platform; PyTorch 1.11 and transformers 4.17 are as in the paper.
\item \textbf{Hardware.} We train on an NVIDIA A100 instead of an RTX 3090, which takes
  about 5 hours instead of 7 for linear regression.
\end{itemize}

  \paragraph{Noisy labels.}
  For noisy labels, the transformer reproduces the double descent curve, see
  Figure~\ref{fig:noisy}.
  \textbf{[Revise: in Table~\ref{tab:linear-repro} the transformer's error rises from 0.47
  at $k=15$ to 0.86 at $k=20$, while least squares rises to 1959. How would you describe
  the transformer's peak?]}
  For minimum norm least squares, the double descent curve appears when plotting test error
  against the number of noisy training samples $n$, for a fixed number of features $p$
  (here $n = k$ and $p = d = 20$).
  For $n < p$, the system is underdetermined and there are infinitely many ways to fit the
  training data exactly, but the minimum-norm solution is chosen. It keeps the weights small,
  effectively spreading the noise over many directions, so predictions on new data stay
  reasonable. As $n$ increases toward $p$, this freedom disappears. At $n = p$ there is a
  unique way to fit the data, so the model is forced to pass through every noisy label. It
  needs large weights, which turn the noise in the training labels into large errors on new
  data, so test error peaks. For $n > p$, the problem is overdetermined and least squares
  improves as $n$ grows, because label noise averages out.
