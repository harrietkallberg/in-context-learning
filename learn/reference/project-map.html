1. The research question

Garg, Tsipras, Liang & Valiant (2022), arXiv:2208.01066. Our copy of their code: dtsip/in-context-learning.

The paper: can a Transformer trained from scratch learn a whole class of functions in context? Each prompt is a few input–output pairs from one function drawn at random, then a new input; the model must predict its output without any weight update. For linear functions it matches least squares, the optimal estimator.

Our work has two parts:

  1. Reproduction. Retrain the paper's four main models (linear, sparse linear, decision tree, 2-layer ReLU net) with the authors' code and compare against their released checkpoints.
  2. Extension: in-context option pricing. A new function class where each prompt is one stock with a hidden volatility. The examples are other options on that stock, (moneyness, maturity) → Black–Scholes price, and the query is a new option. To price it, the model has to calibrate the volatility from the examples, the way a trader backs out implied volatility.

Why this extension? The paper tests synthetic function classes. Option pricing is a real, well-understood task where (a) the exact optimal answer is computable, so there's a hard reference to beat, and (b) the structure is nonlinear and finance-specific (a smile, a term structure), so "does it use the structure?" is a sharp question. It's the first step towards the planned extension B: learning the risk-neutral distribution in context.

  • In-context calibration works. On bs_flat, one example takes the error from 0.15 to 0.003, about 45× below the no-context floor.
  • The smile is used. The bs_smile Transformer reaches 1.5e-5, about 1000× below flat calibration (0.015), so it isn't treating the vol as flat.
  • It beats smile calibration for k ≤ 3 (and up to about k = 20). That's expected: with fewer prices than unknowns, least squares is underdetermined and the Transformer can average over the prior instead. Smile calibration also converges slowly (see gaps).
  • Noisy prices: it tracks calibration (the MLE) down to the 0.0025 noise floor.
  • OTM→ITM and short→long shifts: it generalises well.
  • scale-m=3 fails: the Transformer is worse than the no-context floor, and scale-m=2 on bs_flat is already erratic. Moneyness values far outside training break it, the same failure pattern as the paper's x-scaling tests.

5. What's missing, in the order a reviewer would raise it

  1. The paper isn't written. neurips_2026.tex is still the unedited template, and HANDOFF step 5 (write results into experimental_setup.md) isn't done.
  2. The "optimal" reference isn't exact. With noise-free prices and k ≥ 3, smile calibration should reach ~0 error, yet it sits at 3e-4 at k = 10. The grid + local search runs out of resolution or gets stuck in local minima. Fix: a proper optimiser (Gauss–Newton / L-BFGS from several starts) before calling it the optimum.
  3. No Bayes-optimal baseline for small k and noise. The posterior mean (the average over the prior weighted by fit) is the true optimum where least squares is underdetermined or noisy. A quick simulation at k = 1 (Lesson 3) gives a posterior mean of 0.0099 vs the Transformer's 0.0107, so the model is close to Bayes-optimal there. Making that a real baseline in models.py, for every k and the noisy eval, would turn this into a headline result.
  4. One seed per task. Fine for the reproduction (the paper did the same for these figures). For the new BS claims, a reviewer will ask for 3 seeds.
  5. The scale-m failure isn't analysed. Is it the input range (x₀ up to ±9, never seen), or the price regime? A test that separates the two: same m range but rescaled x.
  6. Relative metric. The shifts move the no-context floor (0.073 to 0.22), so report the Transformer error ÷ prior-mean error per eval.
  7. Modelling simplifications to state: constant r, the smile doesn't depend on maturity, calls only, prices noise-free in training.
  8. What it tests, honestly: inferring 1–3 hidden numbers and applying a fixed formula. That's closer to latent-parameter inference than to the paper's "learning an algorithm". Extension B (risk-neutral density) is what makes the pricing rule itself in-context.
