Lesson 1 · about 10 minutes

One prompt, one hidden function

The whole paper, and our Black–Scholes extension, rest on one idea. Once you can say exactly what is hidden in a prompt and what isn't, everything else (baselines, results, gaps) follows.

Your win for today: describe, for the paper's task and for ours, what changes between prompts, what stays fixed, and which curve proves the model learned in context.

1. The paper's experiment

Garg et al. 2022, arXiv:2208.01066, section 2–3. Abstract: the model learns "unseen linear functions from in-context examples with performance comparable to the optimal least squares estimator."

Pick a function f at random from a class, for example all linear functions f(x) = w·x with w ~ N(0, I₂₀). Draw some inputs x₁ … x_k and write the prompt

x₁, f(x₁), x₂, f(x₂), …, x_k, f(x_k), x_query → ?

The Transformer must predict f(x_query). Its weights are never updated during the prompt, so it has to work out f from the examples it sees: that's in-context learning. Training repeats this with a fresh f every prompt (about 32 million of them), so the only thing worth learning is how to infer f from examples.

Success means matching the best classical algorithm given the same examples. For linear functions that's least squares, which needs about d = 20 examples to pin down 20 unknowns. Our rerun reproduces this: at k = 40 our model's error is 0.014 and the authors' released model's is 0.012.

2. The same slot, in code

Every task in the repo fills the same two-line contract (src/train.py:80-87):

xs   = data_sampler.sample_xs(n_points, b)   # shape (b, n, d)
task = task_sampler()                         # draws one hidden f per prompt
ys   = task.evaluate(xs)                      # shape (b, n)

Axis b = which prompt, so which hidden f. Axis n = position in the prompt. Axis d = the features of one input. Adding a new function class means writing a new Task subclass, and that's exactly what we did.

3. Our swap: f becomes "a stock with hidden volatility"

Black & Scholes 1973, doi:10.1086/260062. Lesson 2 derives the C/S form.

In bs_flat, the hidden f for one prompt is "price a call on a stock whose volatility is σ", with σ ~ U[0.1, 0.5] drawn once per prompt. Each example is an option: x = (x₀, x₁) becomes log-moneyness m and maturity T, and y is its Black–Scholes price. The query is another option on the same stock.

4. The catch: what's fixed can be memorised

In linear regression nothing about f carries over between prompts, so with zero examples the best guess is 0 and the error is large (≈ 20). In our task the whole price surface carries over: a deep in-the-money call is worth a lot whatever σ is. A model can store that in its weights and look clever without reading the examples at all.

That's why we added the BS prior mean baseline (models.py, BSPriorMeanModel). It prices each option at its average over all σ in the prior and ignores the examples. Our real numbers on bs_flat:

At k = 0 the Transformer already sits at 0.146, far below 1. That's memorisation of the fixed surface, not in-context learning. The evidence is the drop below the prior-mean line once examples arrive: 45× lower after one example. Always compare against the prior mean of the same eval, never against 1.

5. Practice

Write the shape of xs for a bs_flat training batch and name each axis.

(64, n_points, 2): 64 prompts (one σ each) × up to 41 positions × 2 features (x₀ → moneyness, x₁ → maturity).

In one sentence: what must the model infer in bs_smile that it doesn't in bs_flat?

How the volatility varies with strike (the skew and curvature of the smile), not just its level. That's 3 hidden numbers instead of 1, so it needs at least 3 examples.

1. In the paper's linear-regression task, what changes from one prompt to the next?

A fresh w is drawn for every prompt. The weights only change between training steps, never within a prompt, and d and the input distribution are fixed.

2. In bs_flat, which quantity is hidden and drawn fresh for every prompt?

σ is sampled once per prompt (sample_params). r is a constant (2%), S is divided out (we price C/S), and T is visible: it's computed from x₁ for each example.

3. With zero examples the Transformer already has error 0.146 on bs_flat, far below 1. Why?

The formula and the x → (m, T) map are the same in every prompt, so the model memorises the average price for each (m, T). That matches the prior-mean baseline (0.157). The query x says nothing about σ.

4. Which comparison is the evidence that our model calibrates volatility in context?

Only the prior-mean line removes what can be memorised. Beating 1 or least squares is easy without reading the examples at all.
