Build the posterior-mean baseline

Lesson 3 showed that the best possible prediction is the average over every volatility consistent with the examples. Now you write it into src/models.py, check it automatically, and find where it can be trusted.

Your win for today: a working BSPosteriorMeanModel that passes 10/10 checks, plus a one-sentence answer to "where is our Transformer Bayes-optimal, and where isn't it?"

1. The idea in one formula

Owen, Monte Carlo theory, methods and examples, ch. 9 (PDF): section 9.2 self-normalised importance sampling, section 9.3 diagnostics.

Draw L parameter sets θ₁ … θ_L from the prior once. For a prompt, weight each by how well it prices the examples seen so far, then average its query price:

ŷi = Σℓ wℓ · priceℓ(xi),    wℓ ∝ exp( −SSEℓ(examples 0 … i−1) / 2τ² )

This is self-normalised importance sampling with the prior as the proposal: the weights are the likelihood. τ is the assumed noise standard deviation of the standardised prices:

  • Noisy eval: the true noise is 0.05, so τ = 0.05 makes this the exact Bayes-optimal predictor (up to Monte Carlo error).
  • Clean evals: the exact answer needs τ → 0, but then almost every sample gets zero weight. A small τ = 0.01 is an approximation, and section 5 shows where it breaks down.

Before you start, predict and write down: on bs_flat at k = 1, will the Transformer (0.0034) be close to the Bayes-optimal error, or far above it?

3. Write it, step by step

Add the class to src/models.py just below BSPriorMeanModel (around line 590). Use that class as your template: it already samples the prior and broadcasts prices over it.

Step 1 — constructor

Signature __init__(self, task_name, prior_samples=8192, tau=0.02). Store self.data_cls = BS_TASKS[task_name], draw self.params with a fixed-seed generator (copy BSPriorMeanModel), store τ, and set self.name = f"bs_posterior_mean_tau={tau}". The name must be unique, because you'll register two instances.

Step 2 — price every option under every prior sample

From xs of shape (b, n, 2), compute m, T = bs_features(xs), add a trailing axis, and get standardised prices of shape (b, n, L). That's the same three calls as in BSPriorMeanModel.__call__.

Step 3 — squared error of the examples before each position

Compute sq = (prices − ys[..., None])², also (b, n, L). The weight at position i must use rows 0 … i−1 only, so take the cumulative sum along n and shift it down by one: prepend a zero row and drop the last row.

The trap: forget the shift and position i sees its own answer yi. The error drops to ~0 and looks like a triumph. The checker's leakage test changes y5 and asserts the prediction at 5 doesn't move.

Step 4 — weights and prediction

Use torch.softmax(-sse / (2 * tau**2), dim=-1). It computes exactly the normalised exp(…) weights without overflow. The prediction is (weights * prices).sum(-1), of shape (b, n). Then handle inds like the other baselines and return pred[:, inds].

Reference solution 
class BSPosteriorMeanModel:
    def __init__(self, task_name, prior_samples=8192, tau=0.02):
        self.data_cls = BS_TASKS[task_name]
        generator = torch.Generator().manual_seed(0)
        self.params = self.data_cls.sample_params(prior_samples, generator)
        self.tau = tau
        self.name = f"bs_posterior_mean_tau={tau}"

    def __call__(self, xs, ys, inds=None):
        xs, ys = xs.cpu(), ys.cpu()
        if inds is None:
            inds = range(ys.shape[1])
        inds = list(inds)
        n = max(inds) + 1  # later positions are never needed
        m, T = bs_features(xs[:, :n])
        m, T = m.unsqueeze(-1), T.unsqueeze(-1)
        vol = self.data_cls.vol(m, self.params)
        prices = self.data_cls.standardize(bs_call_over_spot(m, T, vol))  # (b, n, L)
        sq = (prices - ys[:, :n].unsqueeze(-1)).square()
        # error of examples 0..i-1 for position i: shift the cumsum by one
        sse = torch.cat([torch.zeros_like(sq[:, :1]), sq.cumsum(dim=1)[:, :-1]], dim=1)
        weights = torch.softmax(-sse / (2 * self.tau**2), dim=-1)
        pred = (weights * prices).sum(dim=-1)
        return pred[:, inds]

n = max(inds) + 1 matters for the shift evals, which call the model once per position with inds=[i].

4. Diagnose: effective sample size

Owen ch. 9, eq. (9.13): "If the weights are too imbalanced then the result is similar to averaging only ne ≪ n observations and might therefore be unreliable."

Weighted averages can quietly collapse onto a handful of samples. The effective sample size ne = 1 / Σ wℓ² (for weights that sum to 1) says how many prior samples the prediction really rests on. Add ess = 1 / weights.square().sum(-1) while you experiment.

The story for the paper:

  • bs_smile, few examples: the Transformer matches the Bayes-optimal predictor to two significant figures (0.0107 vs 0.0109; 0.0012 vs 0.0012). This is the headline result.
  • bs_flat, one example: it does not. One price identifies σ exactly, so the optimum is near zero; the Transformer is about 30× above calibration. Its weakness is precision, not inference.
  • Noisy prices: it sits above the true Bayes optimum at small k. That's expected: it was trained on clean prices, so it never learned to discount noise.
  • Trust the posterior only where ESS is large. On clean bs_smile the ESS falls to 1–2 by k = 10, and the "baseline" there is just the nearest prior sample. Report it for k ≤ 3 on clean smiles. For larger k, use calibration with a better optimiser (gap 2).

6. Practice

Write the weight formula and say what τ means.

wℓ ∝ exp(−SSEℓ / 2τ²) over examples 0 … i−1; τ is the assumed noise standard deviation of the standardised prices.

1. Why must the error sum at position i exclude example i?

At position i, yi is the answer being predicted. If it's in the weights, the model just looks it up. All examples in a prompt share one vol model.

2. What does τ represent in the weights exp(−SSE / 2τ²)?

exp(−SSE / 2τ²) is the Gaussian likelihood of the examples under noise with standard deviation τ. When τ equals the true noise, the weighted average is the exact posterior mean.

3. On clean bs_smile data at k = 10 the median ESS is about 2. What follows?

With about 2 effective samples, the "average" is really one or two prior draws, so its error says little about the true optimum. Lowering τ makes the collapse worse; the fix is more samples or a better proposal.

4. On the noisy eval at k = 1, bs_flat's Transformer (0.0167) sits above the posterior with τ = 0.05 (0.0117). Most likely reason?

The Transformer approximates the posterior for the task it was trained on: clean prices. It treats a noisy example as exact. Training with noise is the experiment that would test this.
